# Security hardening — 6 November 2026

This review fixes specific identified paths; it is not a claim that the browser is vulnerability-free.

## Changes

- Electron upgraded from castLabs 44.10.1 to 45.2.1. Runtime and build dependencies are pinned; vulnerable adm-zip/minimatch versions are overridden with reviewed versions.
- Existing profiles migrate once to full site isolation. `site-per-process` explicitly enables the cross-site process boundary. The lower-isolation mode is a deliberate settings opt-out.
- Both remote page views and the local UI run with sandbox and context isolation enabled and Node integration disabled. The browser-action preload is bundled without external Node imports. Incognito UI uses its own in-memory session.
- User-script registration requires the manifest API permission in the main process. Injection and messaging also require host permission, a matching real sender document, the correct session, and an issued script world. Replies are associated with the originating worker/tab. Registration batches, script sizes and pending requests are bounded. Extension file access is disabled by default.
- The pinned upstream Web Store adapter is generated by `tools/prepare-security.js`. CRX3 content signatures are cryptographically verified before extraction. Expected extension ID is checked by the upstream installation path. Legacy CRX2 is rejected. Archives have bounded size, entry count, per-file and total output; unsafe paths, duplicate names and symlinks are rejected. Entry counts are checked before allocation of archive objects.
- Save dialogs use Electron's native asynchronous DownloadItem flow. Final selected paths are recorded and cancelled dialogs do not create bogus download entries.
- HTTP bodies for icons/metadata are bounded while reading, image dimensions are checked, and at most three icon jobs run concurrently. Visible link titles are reused before metadata is fetched. Existing tab DOM and favicon elements are retained when possible.
- A local malicious-domain layer uses the URLhaus and badware lists already bundled with uBO. Packaged builds refresh URLhaus every twelve hours, atomically replacing the cache; stale dynamic domains are removed on refresh. No browsing URL is sent to the feed provider. Blocks show an internal warning page; explicit exceptions last for the window only. This is not a file scanner or the full Google Safe Browsing service.

## Updates and signing

Calcium has no application updater. New versions are installed manually using the setup. Engine security fixes require a new release and installer. uBO filter lists and the local malicious-domain feed may still refresh; these are data updates, not application binaries.

No Windows signing certificate or release credentials were fabricated, purchased or published. A maintainer must configure a real code-signing certificate for release builds (the usual electron-builder `CSC_LINK` / `CSC_KEY_PASSWORD` inputs); the generated `publisherName` must identify the intended publisher. Widevine VMP signatures do not substitute for Windows Authenticode. A signed installer/update cycle cannot be fully validated without the real signing identity and release artifacts.

`dist:*` commands build locally with `--publish never`. Publishing is a separate explicit maintainer action.

## Validation

- `npm run test:security`: permission bypass regression, real RSA CRX3 signature and tamper rejection, archive paths/limits, bounded streams, local domain list replacement and native save-dialog state.
- `npm run test:electron`: actual Electron/ECE tab selection and deferred loading, sandboxed extension icon preload, UI interactions, task manager and manual sleeping.
- `npm audit --audit-level=moderate`: runtime and build dependency advisories.
- `npm run check:engine`: compare the pinned castLabs engine against its official stable release. New engine binaries require rebuilding and releasing Calcium, not downloading executable engine parts into a running browser.

The engine and dependency checks must be repeated before every release; a clean npm audit does not certify the Chromium engine or custom code. Tests of Windows atomic file replacement require normal Windows filesystem access, not a restrictive filesystem sandbox.

## Content blocking

uBlock Origin is the only blocking engine; the Ghostery alternative has been removed. Electron does not support loading extensions into nonpersistent sessions. Private windows retain an in-memory session and route bounded batches of network decisions through the loaded uBO engines, without registering private tabs or request logs in the persistent extension session. This adapter covers static network rules, dynamic URL rules and firewall rules; it does not provide the full extension cosmetic/scriptlet pipeline in private windows. Normal windows use the full extension.
